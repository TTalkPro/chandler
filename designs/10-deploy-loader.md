# 10 — deploy loader 统一:Chandler 接管 `skiff --app`

> 状态:**设计中(2026-07-22)**,K 标号见 §8。
> 前置:[09](09-pack.md)(pack producer 已落地)· [06](06-runtime-compat.md)(双运行时)· [08](08-bootstrap-security.md)(自举分发)。
> 上游规范:[chez-skiff-pack-spec.md](../../skiff/chez-skiff-pack-spec.md)(消费方契约,§4/§5/§6 由本设计落地后修订)。

## 一句话目标

把 skiff 当前持有的 deploy loader(`skiff --app` / `skiff --verify`)整体移交 chandler:`(chandler pack)` 生成的 `bootstrap.ss` 升级为 runtime-aware verifier,**同时**服务 stock-Chez 与 Skiff 两类运行时;skiff 删除 `--app`/`--verify` 语义、统一改用 `skiff --script bootstrap.ss`(与 stock 对称);`pack.manifest` 声明的 `skiff-version`/`skiff-compat` 与当前 runtime 三方组合由 chandler 一处裁决。

## 1. 背景:今天的双 deploy 路径

deploy 路径今天**两套并存**,各跑各的,语义大部分重合但有偏差:

| 路径 | 入口 | 消费方 | 加载什么 | 校验 | 退出码 | 结构化诊断 |
|------|------|--------|----------|------|--------|------------|
| **skiff 路径** | `bin/<mt>/skiff --app pack.manifest` | [`skiff/app.ss`](../../skiff/skiff/app.ss)(C++ main.cpp → `scheme-start` → `skiff-app-main`) | `(mode modules)` 时 `(library-directories (list "<root>/lib"))` + `compile-imported-libraries #f` + `(load-shared-object)` 全部 `(native …)` + `(import <entry>)` + `(<main> …)`;`(mode boot)` 直接 `(top-level-value main-sym)` 调 | `verify-format!`(exit 70)、`verify-target!`(exit 78,机器类型/chez 版本/skiff 版本精确或 compat 区间)、`SKIFF_ALLOW_VERSION_SKEW=1` 逃生阀 | 64 / 65 / 70 / 78 | stderr s-expr `(skiff-app-error (target-mismatch …))` |
| **chandler 路径** | `bin/<mt>/scheme --script bootstrap.ss` | `bootstrap.ss`(由 [`(chandler pack)`](chandler/pack.ss) 生成) | `(library-directories (list (cons %lib %lib)))` + `compile-imported-libraries #f` + `%load-natives`(递归扫 `lib/<mt>/**/native/`)+ `(import <entry>)` + `(<main> …)` | `target-check-src`(lite:只 `chez-version` string=? + `machine-type` eq?,**不查 skiff**) | 错时 `(error 'chandler-pack …)`(Chez 异常,无 sysexits) | 无 |

差异要点:

- **skiff 版本**:skiff 路径查 `(skiff-version "0.4.1")` 精确或 `(skiff-compat ">=0.4 <0.5")` 区间;chandler 路径完全不查,stock pack 跑在 skiff 上等价 stock —— 但反过来不行,**这是把 chandler 路径拖去 runtime-aware 的动机**。
- **格式版本**:`verify-format!` 是 skiff 路径独有的;chandler 路径靠 `(read-manifest)` 自然崩。
- **退出码**:skiff 用 sysexits(64/65/70/78);chandler 用 Chez 异常 + 非零退出。
- **结构化诊断**:skiff 出 stderr s-expr 给 installer 用;chandler 一段字符串。
- **boot 模式**:skiff 路径支持(`(mode boot)` 分支);chandler 路径从来不支持(09-pack.md K4 已废,见 §11)。

## 2. 为什么归 chandler(移交理由)

deploy loader 是 pack 的**消费方**——读 manifest、校验、按装载约定架起运行时。它天生依赖 pack producer 的全部上下文:target 三元组怎么读、native 怎么枚举、`(app)` 字段怎么解、什么算「闭包完整」。这把决定**事实上**已经偏向 chandler:

| deploy loader 需要知道的 | chandler(已具备) | skiff(要新补) |
|---|---|---|
| `pack.manifest` s-表达式格式与白名单 | `(chandler sexp)` + `(chandler manifest)` 全套(09 已用同一份解析 pack) | `skiff/app.ss` 里又写了一遍 `read-manifest` / `field` / `field1` |
| `(target (chez-version …) (machine-type …) (skiff-version …))` 三元组的语义 | 09 §"运行时门"已与 [06](06-runtime-compat.md) 的 `current-runtime` / `skiff-version-string` 协商:stock pack 默认 `(skiff-compat ">=0.0.0")` 即「通吃」 | skiff 自己定义 `verify-target!` 与 `skiff-compat` 区间语法;**事实上** chandler manifest 生成与 skiff 校验两侧漂移 |
| `(format N)` 前向兼容判断 | 09 §"`pack.manifest`" 写 `(format 1)`;L1 把 `verify-format!` 接进来 | skiff 独自持 1,不知道 chandler 哪天升到 2 |
| `(library (entry-lib))` 入口解析 | `(app (entry …))` 解析、拒绝 lib 被打包 —— 同一份 | skiff 走 `(entry-ref m 'library)` 重写 |
| native 落点 + 加载方式 | `%load-natives` 递归扫 + `load-shared-object`(09 §6 §三态同构) | `load-natives!` 走 `(native …)` 段 —— 两份策略等价但实现分叉 |
| `APP_ROOT` 与 `bin/<mt>` 布局 | 启动器 + 布局全栈由 chandler 拥有(09) | skiff 走 `--app pack.manifest`,从 manifest 路径回推包根;**与 chandler 路径**不共享 |
| 完整性(sha256 + size) | `(chandler hash)` 纯 Scheme SHA-256(`chandler verify-pack` 已用) | skiff 用 FFI `skiff_sha256_hex`(链接 OpenSSL) |

裁决与 09 §"为什么归 chandler" 同款延伸并收口:**编译归 bake,组装与部署归 chandler**。skiff 留下的是运行时本身 —— 提供 `skiff --script` + `skiff-version` 的顶层绑定,不掺合 deploy 策略。`skiff --app` 移交完成后,skiff CLI 与 stock `scheme` CLI 完全等价(对齐 [06](06-runtime-compat.md) §2 「Skiff 是 Chez 超集」的支点),runtime 选哪个是**消费方**的事。

## 3. 核心设计:runtime-aware bootstrap

把 09 的 `bootstrap-source` 升级为 **runtime-aware verifier**,生成的 `bootstrap.ss` 在 stock-Chez 与 Skiff 两种运行时上跑同一份,根据当前 runtime 选不同的校验路径。

```scheme
;; 伪代码 —— 仅示意 API 形状,实现期再落实
(define (bootstrap-source entry main-proc ver mt skiff-compat-ver-or-false)
  (string-append
    ";; generated by chandler pack -- do not edit\n"
    bootstrap-root-src
    "(define %rt (if (and (top-level-bound? 'skiff-version)\n"
    "                     (let ([v (top-level-value 'skiff-version)])\n"
    "                       (or (string? v) (procedure? v))))\n"
    "                 'skiff 'chez))\n"
    "(define (%skiff-ver)\n"
    "  (let ([v (top-level-value 'skiff-version)])\n"
    "    (if (procedure? v) (v) v)))\n"
    (target-check-src ver mt)             ; chez-version + machine-type(永远)
    (skiff-target-check-src skiff-compat-ver-or-false)  ; 新增,见下
    "(define %lib (string-append %root \"/lib/" mt "\"))\n"
    "(compile-imported-libraries #f)\n"
    "(library-directories (list (cons %lib %lib)))\n"
    native-walk-src
    "(%load-natives %lib)\n"
    "(import " (datum->str entry) ")\n"
    "(" (symbol->string main-proc) " (cdr (command-line)))\n"
    "(exit 0)\n"))
```

关键变化:

- **runtime 探测复用 [06 §4](06-runtime-compat.md) 的同款逻辑**:`(top-level-bound? 'skiff-version)` 判存在;`(top-level-value 'skiff-version)` 取值后,**字符串/过程两形都认**(skiff 0.1.1 起绑为过程,见 [`(chandler runtime)`](chandler/runtime.ss) `skiff-version-string` 的同款守卫)。这是 [06](06-runtime-compat.md) §4 2026-07-22 修订钉死的容忍,**一字不改照搬**,bootstrap 与 `activate` 同源。
- **不再生成两份** `bootstrap.ss` —— 现 09 §6 「`bootstrap-source` 仅 stock 运行时;skiff 的加载全在 `skiff --app` 里」的分叉取消。**所有包**都生成 bootstrap.ss,skiff 包同样跑它,启动器改用 `skiff --script bootstrap.ss`(§6)。
- **stock 包的 `skiff-compat ">=0.0.0"` 默认**保留(09 §`manifest-head` 第 442 行):全开区间下,任何 skiff 版本都「通过」,同一份 stock pack 既能跑 `bin/<mt>/scheme --script bootstrap.ss`,也能跑 `bin/<mt>/skiff --script bootstrap.ss`。这是 09 §"三态同构" + [06](06-runtime-compat.md) §1 ★ 的核心。

> **对齐 skiff/app.ss 的结构**:探到 skiff 后,从 `(top-level-value 'skiff-version)` 取字符串(过程则调用)作为 actual;`(skiff-compat "<range>")` 走 `version-in-range?`(与 [`skiff/app.ss` §`version-in-range?`](../../skiff/skiff/app.ss) 同一份实现;不在本设计里重写;直接 `(import (chandler version))` 复用)。

## 4. 双运行时校验规则(矩阵)

下面是 runtime-aware verify-target 的完整决策表 —— 行列交叉即 exit code(没有则为空 = 通过):

| manifest 声明 | 当前 runtime | 校验动作 | 失败 exit code |
|---|---|---|---|
| `(skiff-version "0.4.1")` | skiff(任意版本) | `(skiff-version)` 返回值(过程则调)精确等于 `"0.4.1"` | 78 |
| `(skiff-version "0.4.1")` | skiff(版本不符) | 同上,值不等 | 78 |
| `(skiff-version "0.4.1")` | stock Chez | **拒绝**:pack 要求 skiff,当前 runtime 不是 | 78 |
| `(skiff-compat ">=0.4 <0.5")` | skiff(0.4.x) | `version-in-range?` 通过 | — |
| `(skiff-compat ">=0.4 <0.5")` | skiff(0.5.0) | 超出区间 | 78 |
| `(skiff-compat ">=0.4 <0.5")` | stock Chez | **拒绝**:pack 要求 skiff,当前 runtime 不是 | 78 |
| `(skiff-compat ">=0.0.0")`(全开,09 §`manifest-head` 第 442 行 stock pack 默认值) | skiff(任意) | 全开,通过 | — |
| `(skiff-compat ">=0.0.0")`(全开) | stock Chez | 通过(全开下 stock 也是合法 runtime,声明不挑) | — |
| 无 `(skiff-version …)` / 无 `(skiff-compat …)` | 任意 | 不校验 skiff | — |
| 任意 + `SKIFF_ALLOW_VERSION_SKEW=1` + skiff 不符 | skiff | WARNING + 通过(逃生阀,**只**放宽 skiff-version,不动 chez/machine-type) | — |
| `(chez-version "10.4.1")` | 任意 | `(chez-version-string)` 精确等于(fasl ABI 绑版本) | 78 |
| `(machine-type ta6le)` | 任意 | `(machine-type)` `eq?` 精确(架构/OS 绑定) | 78 |
| `(format N)` where `N > pack-format-supported` | 任意 | 拒绝(前向兼容) | 70 |

矩阵的几条**不变式**:

- **machine-type 与 chez-version 永不放宽**:fasl 物理上载不动,SKIFF_ALLOW_VERSION_SKEW 也只放宽 skiff(对齐 skiff/app.ss §5 `skew-ok?` 仅作用于 skiff-version)。
- **「pack 要求 skiff 而 runtime 是 stock Chez」一律 78**:无论 `(skiff-version …)` 精确还是 `(skiff-compat …)` 区间。这是 09 §"运行时门" 与 [06](06-runtime-compat.md) §3 「应用若真需要 skiff,`manifest.ss` 就该声明 `(skiff ">=…")`」落到 deploy 侧的镜像。
- **stock 包(全开 `">=0.0.0"`)在两种 runtime 上都通过**:这是 chandler 与 skiff 共用一份 pack 的关键 —— 不强制声明,默认就是「通吃」。
- **缺 `(target …)` 字段**:exit 65(EX_DATAERR,与 [skiff/app.ss `read-manifest`](../../skiff/skiff/app.ss) 同款拒)。

## 5. 结构化诊断(对齐 skiff/app.ss)

`bootstrap.ss` 出错时不再用 Chez 的 `(error 'chandler-pack …)`,**沿用 skiff 的 sysexits + stderr s-expr**:

| 失败类型 | exit code | stderr 文本 | stderr s-expr |
|----------|-----------|-------------|----------------|
| `(format N)` 超出 | 70 EX_SOFTWARE | `chandler-pack: pack format N is newer than supported (1)` | `(chandler-pack-error (format-too-new (pack N) (supported 1)))` |
| 缺 `(target …)` / manifest 不可读 | 65 EX_DATAERR | `chandler-pack: manifest missing/invalid: …` | `(chandler-pack-error (manifest-invalid …))` |
| target 三元组不匹配(任何分量) | 78 EX_CONFIG | 逐项 expected vs actual + 修复建议 | `(chandler-pack-error (target-mismatch (machine-type (expected …) (actual …)) (chez-version …) (skiff-version …)))` |
| skiff-version + `SKIFF_ALLOW_VERSION_SKEW=1` | — | `WARNING: skiff-version skew allowed by SKIFF_ALLOW_VERSION_SKEW=1 (pack …, runtime …)` | — |

- **进程退出码由 bootstrap.ss 显式 `(exit N)` 抛出**,不走 Chez 异常路径 —— 异常会进 Chez debugger / 留下栈帧,deploy 进程不要这个。
- **结构化 s-expr 始终单行、无换行**:`installer` / orchestrator 用 `read` 收。
- **diagnostic 文案与 skiff/app.ss §`verify-target!` 保持同款措辞**(下移到 `(chandler pack)` 一份):「`machine-type` 不符 → wrong platform pack;fetch the build for this machine-type」「`chez`/`skiff` 版本不符 → install the matching runtime or re-pack the app」—— 同一份 wordings 在两处出现,实现时抽 `(chandler pack diagnostic)` 共享。

> **不再分 `--app` / `--verify` 两个 stderr 前缀** —— skiff 删除后只有一份 `chandler-pack:` 前缀;`verify-pack` 走另一路径(见 §7)。

## 6. skiff 模式 launcher 改造

启动器层只改两行,把 `skiff --app pack.manifest` 换成 `skiff --script bootstrap.ss`,与 stock 对称:

```sh
# 现状(pack.ss:309-314,生成器内部)
exec "$HERE/bin/$MT/skiff" --app "$HERE/pack.manifest" "$@"

# 新版(L2)
exec "$HERE/bin/$MT/skiff" --script "$HERE/bootstrap.ss" "$@"
```

```ps1
# 现状(pack.ss:316-322)
& "$Here/bin/$MT/skiff.exe" --app "$Here/pack.manifest" @PackArgs
# 新版
& "$Here/bin/$MT/skiff.exe" --script "$Here/bootstrap.ss" @PackArgs
```

skiff runtime **无需任何改动**:

- `main.cpp:290` `skiff_runtime_start()` 在 `apply_settings` 之前无条件跑,任何 `--script` 都拿到 libuv loop(09 §"自举与启动器"已用此路径)。
- `main.cpp:286` `signal_exit = opts.script || opts.program || opts.app_mode` —— `--script` 与原 `--app` 走同一条「^C 直接退进程」分支,**不需要单独加 `app_mode` 判定**。
- bootstrap.ss 的 `(import (skiff …))` 自动拿到 libuv、task runtime 等,不需要 skiff 端的「deploy mode」flag。
- `SKIFF_BOOT_DIR` 仍由启动器显式 export(`bin/<mt>` + `boot/<mt>` 布局对不上 skiff 的 exe 相对发现,见 [09](09-pack.md) §"env:去两个,留一个,换中性前缀" 注脚);L2 不动这条。

## 7. verify-pack 升级

`chandler verify-pack <dir|pack.manifest>` 现在只跑完整性(sha256 + size),L1 加两块:

### 7a. `verify-format!`

manifest 头的 `(format N)` 大于 `pack-format-supported`(=1)即 exit 70,与 skiff/app.ss 同款;当前 `verify-pack` 隐式靠 `(read)` 崩,错误信息不可控。

### 7b. `--target` flag

新加可选 flag:`chandler verify-pack --target <dir|pack.manifest>`,触发完整 verify-target!(§4 矩阵),对当前正在跑的 runtime 做所有 target 三元组校验;不带则保持现状(只查完整性)。

```text
chandler verify-pack [--target] <dir|pack.manifest>
  --target  跑 verify-target! 矩阵(本机 vs manifest 声明);不带则只查文件完整性
```

### 7c. 退出码对齐 sysexits

| 当前 | 新(L1) | 含义 |
|------|---------|------|
| 0 | 0 | 全 OK |
| 70 | **65** EX_DATAERR | 文件缺失 / sha256 不符 / size 不符(`verify-pack` 本职) |
| — | **70** EX_SOFTWARE | `(format N)` 超出支持 |
| — | **78** EX_CONFIG | `--target` 触发,任何 target 分量不匹配 |

> **70 → 65 的回归**:此前完整性错用 70 EX_SOFTWARE,与 skiff 路径(skiff/app.ss `skiff-verify-main` 用 65)不一致;**L1 改为 65**,对齐 `chez-skiff-pack-spec.md` §5 退出码表。
